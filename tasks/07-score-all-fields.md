# Task 7: Score every field and line items

**Build order item:** 7, 8, 9 (field and document-type slices)
**Status:** todo
**Depends on:** task 6

## Goal

The scorecard classifies every field of every document as correct, wrong
value, missed or hallucinated, and scores line items by row. It is built from
saved runs only, so existing runs can be rescored with no API calls.

Why now: `total` alone is 6 of 6 and hides the real failures. Every later
decision (prompt v2, abstention threshold, the optimization) is judged on
these numbers.

## Files

- `evals/scoring.py` — new. Field comparison, merchant matching, line-item
  matching. Pure functions, no I/O.
- `evals/run_eval.py` — changed. `score()` uses `scoring.py`; summary and
  per-document blocks cover every field.
- `tests/test_scoring.py` — changed. Import `classify` from `evals.scoring`;
  add cases for the new rules.
- `outputs/runs/20261007-051452/scorecard.json`,
  `outputs/runs/20261007-083154/scorecard.json` — regenerated by `--rescore`.

## Steps

1. **Move `classify`** into `evals/scoring.py` unchanged. `run_eval.py`
   imports it from there.
2. **Fields scored.** The eight value fields `merchant_name`,
   `transaction_date`, `subtotal`, `discount`, `service_charge`, `tax`,
   `total`, `payment_method` go through `classify`. `document_type` has no
   status, so it is only `correct` or `wrong_value`, reported in its own block
   and not counted in the eight.
3. **Merchant name.** Correct when, after casefolding and collapsing
   whitespace, the value equals the label or any `accept` entry, or when the
   `rapidfuzz` `fuzz.ratio` against any of them reaches `MERCHANT_THRESHOLD =
   90`. A named constant with a comment; tests show one name just above and
   one just below.
4. **Everything else is exact.** Amounts as integers, dates as the ISO string,
   payment method as the literal.
5. **Line items.** A predicted row matches a truth row when `amount` is equal,
   `quantity` is equal within 0.01 (`None` equals `None`), and the description
   `fuzz.token_set_ratio` is at least `DESCRIPTION_THRESHOLD = 60`. Match
   greedily, best description first, each row used once. Report matched,
   missing (truth rows with no match) and extra (predicted rows with no match)
   per document, and row precision and recall over the run.
6. **Per document** in the scorecard: for each field, the expected value,
   extracted value, status, confidence and class; the line-item counts.
7. **Summary:**
   - per field: counts of each class and accuracy
   - over the eight value fields: correct out of total
   - `hallucinated` total on its own line
   - by document type and by split: correct out of total over the eight
   - line items: matched, missing, extra, precision, recall
   - an `error` document counts every field as `error`
8. **Run block.** Replace `field_scored` with `fields_scored` (the list).
   When rescoring, drop the old `field_scored` key from the kept run block.
9. **Rescore both committed runs** and commit the regenerated scorecards.
10. **Tests**, no network: merchant accept list and threshold, a printed zero
    is correct, hallucination and miss on the same field, line-item matching
    with a repeated row, an extra row and a row with no amounts (handwritten),
    summary counts on a small run folder in a temp directory.
